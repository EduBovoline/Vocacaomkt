Por que sites lentos perdem clientes e como corrigir Core Web Vitals

O que são LCP, INP e CLS, os limites oficiais de cada métrica, a diferença entre nota do PageSpeed e dados de campo e como corrigir cada problema.

Pense no seu cliente no ônibus, com 4G oscilando, clicando no link do seu site. A tela fica branca. Depois aparece um banner que empurra o texto para baixo. Ele tenta tocar no botão do WhatsApp e nada acontece por um segundo inteiro. Na segunda tentativa, ele já voltou para o Google e clicou no concorrente.

Ninguém reclama de site lento. A pessoa só vai embora. Por isso o problema passa despercebido por meses: não gera ligação de cliente bravo, só gera um número menor de contatos no fim do mês.

O Google mede exatamente essa experiência com três métricas chamadas Core Web Vitals. Elas entram nos sistemas de classificação da busca e, mais do que isso, são um retrato fiel de quanta paciência você está exigindo de quem chega.

As métricas em linguagem de gente

LCP: quanto tempo até aparecer o que importa

O Largest Contentful Paint mede quanto tempo leva para o maior elemento visível da primeira tela aparecer. Normalmente é a imagem principal, o vídeo de capa ou o título grande.

  • Bom: até 2,5 segundos.
  • Precisa melhorar: entre 2,5 e 4 segundos.
  • Ruim: acima de 4 segundos.

INP: quanto tempo o site demora para reagir

O Interaction to Next Paint substituiu o antigo FID em março de 2024. Ele observa os cliques, toques e digitações durante toda a visita e registra quanto tempo a página demora para mostrar alguma resposta visual.

  • Bom: até 200 milissegundos.
  • Precisa melhorar: entre 200 e 500 milissegundos.
  • Ruim: acima de 500 milissegundos.

Um INP alto é aquele botão que parece travado. A pessoa toca duas, três vezes, e às vezes envia o formulário em duplicidade.

CLS: quanto a página pula enquanto carrega

O Cumulative Layout Shift mede deslocamentos inesperados de layout. É o texto que desce quando um anúncio carrega, ou o botão que muda de lugar no exato momento do toque.

  • Bom: até 0,1.
  • Precisa melhorar: entre 0,1 e 0,25.
  • Ruim: acima de 0,25.

Nota do PageSpeed não é a mesma coisa que Core Web Vitals

Essa confusão aparece em quase toda reunião. O PageSpeed Insights mostra duas coisas diferentes na mesma tela.

A parte de cima traz os dados de campo, coletados de usuários reais do Chrome nos últimos 28 dias (o relatório CrUX). É isso que o Google usa para avaliar Core Web Vitals. Para passar, a página precisa ficar na faixa "bom" em pelo menos 75% das visitas, nas três métricas.

A parte de baixo traz a nota de 0 a 100, gerada pelo Lighthouse numa simulação de laboratório. Acima de 90 aparece verde, entre 50 e 89 laranja e abaixo de 50 vermelho. Ela é ótima para diagnosticar, mas não é a nota que entra na busca.

Então, qual a nota mínima? Não existe uma nota oficial de corte. Nossa referência de trabalho é: Core Web Vitals aprovados nos dados de campo e Lighthouse mobile acima de 90 nas páginas que vendem (home, serviços, landing pages). Site pequeno, sem tráfego suficiente, muitas vezes nem tem dados de campo. Nesse caso o laboratório é o único termômetro disponível.

O peso real no ranking

Vale ser honesto aqui. Core Web Vitals fazem parte dos sinais de experiência de página que o Google usa, mas relevância do conteúdo continua pesando muito mais. Um site rápido e raso não passa na frente de um site um pouco mais lento que responde melhor a busca.

O efeito da velocidade aparece com mais força em dois pontos. No desempate entre páginas parecidas, e principalmente depois do clique, quando o visitante decide se fica ou se volta. Uma página que carrega em 1,5 segundo e outra que carrega em 6 podem até ter a mesma posição no Google. O faturamento delas é que não vai ser o mesmo.

O que mais derruba cada métrica (e como corrigir)

Para melhorar o LCP

O culpado número um é imagem de capa pesada. Não é raro encontrar foto de 4 MB em JPEG sendo carregada para um espaço de 400 pixels na tela do celular. O mesmo vale para GIF animado na primeira dobra, que costuma pesar vinte vezes mais que um vídeo equivalente.

O que resolve:

  1. Converter imagens para WebP ou AVIF e entregar tamanhos diferentes para celular e desktop com srcset.
  2. Trocar GIF por vídeo .webm e .mp4 mudo em loop, com uma imagem poster leve.
  3. Não aplicar loading="lazy" na imagem principal da primeira tela. Lazy load é para o que está abaixo da dobra.
  4. Usar fetchpriority="high" na imagem que é o maior elemento.
  5. Reduzir o tempo de resposta do servidor com cache e CDN.

Para melhorar o INP

INP ruim quase sempre é excesso de JavaScript rodando na thread principal. Chat de atendimento, pixel de três ferramentas de anúncio, mapa de calor, pop-up de cupom, tudo carregando ao mesmo tempo.

Comece fazendo um inventário honesto de scripts de terceiros e pergunte quem ainda usa cada um. Os que ficarem podem carregar depois da interação ou com atraso. Em sites construídos com frameworks pesados, quebrar tarefas longas e evitar re-renderizações desnecessárias faz diferença visível.

Para melhorar o CLS

Toda imagem, vídeo e iframe precisa ter width e height definidos no HTML, ou um aspect-ratio no CSS, para o navegador reservar o espaço antes do arquivo chegar. Banners de cookie e avisos devem sobrepor o conteúdo, e não empurrá-lo. Fontes personalizadas pedem font-display: swap e, se possível, pré-carregamento, para o texto não mudar de tamanho quando a fonte carrega.

Como medir sem se enganar

Teste sempre a versão mobile primeiro. É onde está a maior parte do tráfego e onde os problemas aparecem. Rode o PageSpeed Insights mais de uma vez, porque a nota de laboratório varia de uma execução para outra. Depois acompanhe o relatório "Core Web Vitals" no Google Search Console, que agrupa URLs com o mesmo problema e mostra a evolução real depois das correções.

Mais um cuidado: dados de campo levam até 28 dias para refletir uma melhoria. Corrigiu hoje, o laboratório mostra na hora. O relatório de campo vai mostrar ao longo das próximas semanas.

Perguntas frequentes

O que é LCP e qual o valor ideal? LCP (Largest Contentful Paint) é o tempo até o maior elemento visível da primeira tela aparecer, geralmente a imagem principal ou o título. O ideal é ficar em até 2,5 segundos. Acima de 4 segundos é considerado ruim.

O que é INP e por que ele substituiu o FID? INP (Interaction to Next Paint) mede quanto tempo a página leva para responder visualmente a cliques, toques e digitação durante toda a visita. Ele substituiu o FID em março de 2024 porque o FID só avaliava a primeira interação. O ideal é ficar em até 200 milissegundos.

Qual a nota mínima no PageSpeed Insights? Não existe nota mínima oficial. A nota de 0 a 100 vem de um teste de laboratório e não é usada diretamente no ranking. O que conta são os Core Web Vitals nos dados de campo, que precisam estar na faixa boa em 75% das visitas. Como referência prática, buscamos nota acima de 90 no mobile nas páginas comerciais.

Core Web Vitals ruins tiram meu site do Google? Não. Eles são um dos sinais de experiência de página, e a relevância do conteúdo pesa mais. O impacto maior de um site lento está na conversão: visitantes que desistem antes de ver a oferta ou de tocar no botão de contato.
