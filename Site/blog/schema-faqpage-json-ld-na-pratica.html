Schema FAQPage e JSON-LD: guia prático para aparecer nos AI Overviews

Como montar e validar schema FAQPage em JSON-LD, o que ele faz pelo seu site, por que não é fator de ranking e como ele ajuda na leitura por IAs.

Vamos começar pelo que pouca agência fala: desde agosto de 2023, o Google só mostra o resultado expandido de FAQ (aquelas perguntas que abriam embaixo do link) para sites governamentais e de saúde com autoridade reconhecida. Se alguém te vendeu schema FAQPage prometendo aquele "sanfona" de perguntas no resultado de busca, essa promessa ficou velha.

Mesmo assim, a gente continua colocando FAQPage em quase todo conteúdo que publica. O motivo mudou. Hoje o valor do schema está em deixar o conteúdo legível para máquinas, num momento em que boa parte das respostas é montada por sistemas que leem, resumem e citam páginas. Este guia mostra como fazer isso direito, o que o schema faz e o que ele não faz.

O que é JSON-LD e onde o FAQPage entra

JSON-LD é um formato de dados estruturados que você cola dentro de uma tag <script type="application/ld+json"> no HTML. Ele descreve, no vocabulário do Schema.org, o que existe na página: um artigo, uma empresa, um produto, uma lista de perguntas e respostas.

O Google aceita três formatos (JSON-LD, Microdata e RDFa) e recomenda o JSON-LD. Na prática ele é o mais fácil de manter, porque fica num bloco separado e não exige mexer no HTML visível.

O FAQPage é um dos tipos do Schema.org. Ele organiza a página como uma lista de Question, cada uma com um acceptedAnswer do tipo Answer. A estrutura mínima é esta:

{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "Qual o prazo de entrega de uma landing page?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Entre 10 e 15 dias úteis depois da aprovação do briefing e do envio dos textos e imagens."
      }
    }
  ]
}

Schema afeta ranking? A resposta honesta

Não diretamente. O próprio Google já repetiu em várias ocasiões, pela documentação do Search Central e por porta-vozes como John Mueller, que dados estruturados não são fator de ranqueamento. Uma página não sobe de posição só porque ganhou um bloco de JSON-LD.

O que o schema faz é reduzir ambiguidade. Ele diz ao rastreador, sem margem para interpretação, que aquele trecho é uma pergunta e aquele outro é a resposta oficial. Na prática, isso rende duas coisas:

  • Elegibilidade para resultados enriquecidos que ainda existem, como produto, avaliação, breadcrumb e artigo.
  • Leitura mais limpa por crawlers de IA, que precisam separar conteúdo útil do ruído de menu, rodapé e scripts. Quanto menos o sistema precisa adivinhar, menor a chance de o resumo gerado contradizer o que o seu site afirma.

Sobre os AI Overviews, vale ser preciso: o Google afirma que não existe marcação especial obrigatória para aparecer neles. As mesmas boas práticas de SEO valem. Ninguém sério pode garantir que um schema coloca sua página no resumo de IA. O que dá para garantir é que, quando o sistema for buscar a resposta, ela vai estar organizada, visível e fácil de extrair. Isso aumenta a chance, não cria certeza.

Como montar um FAQPage que funciona

1. Escreva o FAQ para pessoas primeiro

O erro mais comum é criar perguntas só para encher o schema. O Google exige que todo conteúdo marcado esteja visível na página. Se a pergunta existe no JSON-LD e não existe no texto, isso pode ser tratado como marcação enganosa.

Comece pelas perguntas que seu comercial ouve toda semana. "Tem pedido mínimo?", "Atende fora da capital?", "Quanto tempo demora?". Pergunta real gera resposta específica, e resposta específica é o que um modelo de IA consegue citar.

2. Responda na primeira frase

Uma resposta boa para schema começa respondendo. "Sim, atendemos todo o Brasil de forma remota" funciona. "Essa é uma dúvida muito comum entre nossos clientes e depende de vários fatores" não funciona, nem para o leitor nem para a máquina.

Mantenha cada resposta entre duas e cinco frases. Se precisar de mais que isso, provavelmente o assunto merece uma seção própria no artigo, e não uma linha de FAQ.

3. Mantenha texto idêntico entre página e schema

O texto do campo text deve ser o mesmo da resposta visível, ou uma versão fiel e resumida dela. Quando a página diz "15 dias" e o JSON-LD diz "10 dias", você criou duas versões da verdade. Sistemas automatizados não sabem qual escolher, e a confiança no domínio cai.

4. Combine com Article usando @graph

Num post de blog, faz sentido declarar o artigo e o FAQ no mesmo bloco. O @graph permite isso sem duplicar @context:

{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Article",
      "headline": "Título do artigo",
      "datePublished": "2026-11-24",
      "author": { "@type": "Organization", "name": "Nome da empresa" }
    },
    {
      "@type": "FAQPage",
      "mainEntity": []
    }
  ]
}

Use uma única marcação FAQPage por página. Se o site tem uma página central de perguntas frequentes, não replique as mesmas perguntas em todos os posts.

Como validar antes de publicar

Duas ferramentas resolvem quase tudo, e cada uma olha para uma coisa diferente.

O Teste de pesquisa aprimorada do Google (search.google.com/test/rich-results) mostra se a página é elegível para algum resultado enriquecido e aponta erros que impedem essa elegibilidade. Como o FAQ expandido ficou restrito, é normal ele não listar o FAQPage como elegível para sites comuns. Isso não significa que o código está errado.

O Schema Markup Validator (validator.schema.org) verifica se a estrutura segue o vocabulário do Schema.org, sem se preocupar com regras do Google. É o melhor jeito de confirmar que o JSON está sintaticamente correto e que os tipos estão bem aninhados.

Nosso roteiro de checagem antes de subir qualquer página:

  1. Colar a URL publicada (ou o código) no Schema Markup Validator e zerar erros.
  2. Rodar o Teste de pesquisa aprimorada para ver se algo quebrou a leitura da página.
  3. Abrir o código-fonte e conferir se o JSON-LD aparece no HTML entregue pelo servidor, e não só depois que o JavaScript roda.
  4. Comparar, pergunta por pergunta, o texto do schema com o texto visível.

O item 3 pega muita gente. Em sites que montam tudo no navegador, o JSON-LD pode até existir para o Googlebot, que renderiza JavaScript, mas não existir para crawlers mais simples. Se a ideia é ser lido por IA, o bloco precisa estar no HTML inicial.

Erros comuns em auditorias de schema

O mais frequente é schema copiado de outro site, com perguntas que não têm nada a ver com a página. Logo atrás vem o JSON-LD com variáveis de template sem preencher, do tipo {{pergunta_1}}, publicado em produção por meses sem ninguém notar.

Também aparece bastante o FAQ usado como depósito de palavras-chave, com perguntas forçadas para encaixar termos de busca. Isso costuma piorar a leitura humana e não ganha nada em troca.

Por fim, plugins de SEO que geram FAQPage automaticamente em todas as páginas, inclusive em categorias de produto e na página de contato. Marcação em excesso dilui o sinal e cria duplicidade.

Perguntas frequentes

Schema JSON-LD afeta o ranking no Google? Não diretamente. Dados estruturados não são fator de ranqueamento. Eles ajudam o Google e outros sistemas a entender o conteúdo, podem tornar a página elegível para alguns resultados enriquecidos e facilitam a extração de respostas por ferramentas de IA.

O Google ainda mostra o resultado expandido de FAQ? Desde agosto de 2023, o resultado expandido de FAQ aparece apenas para sites governamentais e de saúde com autoridade reconhecida. Para os demais, a marcação continua válida, mas não gera mais as perguntas abertas no resultado de busca.

Como validar o schema FAQPage? Use o Schema Markup Validator (validator.schema.org) para checar a estrutura e o Teste de pesquisa aprimorada do Google para ver a elegibilidade a resultados enriquecidos. Depois confira no código-fonte se o JSON-LD está no HTML entregue pelo servidor e se o texto bate com o conteúdo visível.

Preciso de schema especial para aparecer nos AI Overviews? Não. O Google afirma que não há marcação obrigatória para os AI Overviews. Um FAQPage bem feito ajuda porque organiza respostas diretas e visíveis, mas não garante a citação.
